# Data Model: Cloud Hosting Infrastructure

**Feature**: 001-cloud-hosting  
**Date**: 2025-01-27

## Core Entities

### Deployment Configuration
**Purpose**: Manages deployment settings and environment configuration

**Attributes**:
- `environment`: string (development, staging, production)
- `version`: string (semantic versioning)
- `services`: array of service configurations
- `resources`: object (CPU, memory, storage limits)
- `secrets`: object (API keys, database credentials)

**Relationships**:
- Contains multiple Service instances
- References Environment variables

### Service Configuration
**Purpose**: Defines individual service deployment parameters

**Attributes**:
- `name`: string (mcp-server, messenger-client, mcp-bridge)
- `image`: string (Docker image name and tag)
- `ports`: array of port mappings
- `environment_vars`: object (service-specific environment variables)
- `health_check`: object (endpoint, interval, timeout)
- `scaling`: object (min_instances, max_instances, target_cpu)

**Relationships**:
- Belongs to Deployment Configuration
- Has Health Check endpoints

### API Endpoint
**Purpose**: Defines API gateway routing and configuration

**Attributes**:
- `path`: string (URL path pattern)
- `method`: string (HTTP method)
- `target_service`: string (backend service name)
- `authentication_required`: boolean
- `rate_limit`: object (requests_per_minute, burst_limit)
- `caching`: object (enabled, ttl_seconds)

**Relationships**:
- Routes to Service Configuration
- Has Rate Limiting rules

### Health Check
**Purpose**: Monitors service health and availability

**Attributes**:
- `service_name`: string
- `endpoint`: string (health check URL)
- `interval_seconds`: integer
- `timeout_seconds`: integer
- `retry_count`: integer
- `status`: string (healthy, unhealthy, unknown)
- `last_check`: timestamp
- `response_time_ms`: integer

**Relationships**:
- Monitors Service Configuration
- Generates Alert instances

### Alert
**Purpose**: Represents system alerts and notifications

**Attributes**:
- `id`: string (unique identifier)
- `type`: string (health, performance, security)
- `severity`: string (low, medium, high, critical)
- `message`: string (alert description)
- `service_name`: string
- `timestamp`: timestamp
- `resolved`: boolean
- `resolved_at`: timestamp (nullable)

**Relationships**:
- Generated by Health Check
- Can reference multiple services

### API Key
**Purpose**: Manages authentication for third-party applications

**Attributes**:
- `key_id`: string (unique identifier)
- `key_value`: string (hashed/encrypted)
- `application_name`: string
- `permissions`: array of strings (allowed endpoints)
- `rate_limit`: object (requests_per_minute)
- `created_at`: timestamp
- `expires_at`: timestamp (nullable)
- `active`: boolean

**Relationships**:
- Authorizes API Endpoint access
- Belongs to Application

## State Transitions

### Service Health Status
```
unknown → healthy (service responds successfully)
unknown → unhealthy (service fails health check)
healthy → unhealthy (service starts failing)
unhealthy → healthy (service recovers)
```

### Alert Lifecycle
```
created → acknowledged → resolved
created → resolved (auto-resolved)
```

### API Key Lifecycle
```
active → suspended (temporary disable)
suspended → active (re-enable)
active → revoked (permanent disable)
```

## Validation Rules

### Deployment Configuration
- Environment must be one of: development, staging, production
- Version must follow semantic versioning (MAJOR.MINOR.PATCH)
- Resources must have positive values for CPU and memory

### Service Configuration
- Port mappings must not conflict
- Health check endpoint must be valid URL
- Scaling limits: min_instances ≤ max_instances

### API Endpoint
- Path must start with '/'
- Method must be valid HTTP method
- Rate limit must be positive integer

### Health Check
- Interval must be ≥ 10 seconds
- Timeout must be < interval
- Retry count must be ≥ 1

### API Key
- Key value must be unique
- Expiration date must be in future (if set)
- Permissions must reference valid endpoints
